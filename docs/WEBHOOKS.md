# Вебхуки подписки → шлюз TIREK

Документ для разработчиков площадки. Описывает **нейтральный формат** шлюза. Если площадка
шлёт события в своём формате, шлюз переводит их в этот формат адаптером
(для BB-маркета — `gateway/adapters/bbmarket.py`); подпись и ответы от этого не меняются.

## Куда слать

```
POST https://<домен шлюза>/webhooks
Content-Type: application/json
X-Tirek-Timestamp: <unix-время отправки, секунды>
X-Tirek-Signature: sha256=<подпись>
```

## Подпись

Общий секрет выдаёт TIREK (у шлюза — переменная `WEBHOOK_SECRET`), передаётся вне репозиториев.

```
подпись = hex( HMAC-SHA256( секрет, "<X-Tirek-Timestamp>." + <тело запроса байт в байт> ) )
```

- подписывается **сырое тело** ровно в том виде, в каком уходит в запросе (без переформатирования JSON);
- метка времени — часть подписанной строки, отдельно её подменить нельзя;
- шлюз принимает метку времени в пределах окна `WEBHOOK_TOLERANCE_SECONDS` от своих часов
  (по умолчанию 300 с, значение согласуется с площадкой) — в обе стороны;
- сравнение подписи — за постоянное время.

### Пример

Секрет `example-secret`, `X-Tirek-Timestamp: 1792000000`, тело (одна строка):

```json
{"event_id":"evt_0001","type":"subscription.purchased","account_id":"company-42","plan":"pro","occurred_at":"2026-10-14T10:00:00Z"}
```

Подписывается строка `1792000000.{"event_id":"evt_0001",…}`, результат:

```
X-Tirek-Signature: sha256=9e504b98d3edc71508569afc51912281c039c97460e90f0448e0dc8f41059bbe
```

Python:

```python
import hashlib, hmac, json, time, httpx

body = json.dumps(event, separators=(",", ":"), ensure_ascii=False).encode()
ts = str(int(time.time()))
sig = hmac.new(SECRET.encode(), ts.encode() + b"." + body, hashlib.sha256).hexdigest()
httpx.post(
    URL,
    content=body,
    headers={
        "Content-Type": "application/json",
        "X-Tirek-Timestamp": ts,
        "X-Tirek-Signature": f"sha256={sig}",
    },
)
```

## Событие

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `event_id` | строка | да | уникальный id события у площадки; повтор с тем же id не выполняется второй раз |
| `type` | строка | да | тип, см. ниже |
| `account_id` | строка | да | id аккаунта (компании) покупателя на площадке |
| `plan` | строка | для смены тарифа | id тарифа площадки |
| `occurred_at` | строка ISO 8601 с часовым поясом | да | когда событие произошло у площадки |

Персональные данные (имена, почты, телефоны) **не передавайте** — шлюзу они не нужны.

| `type` | Что делает TIREK |
|---|---|
| `subscription.purchased` | создаёт организацию-арендатора (тариф по `PLAN_MAP`, иначе `plugin`) и делает её активной |
| `subscription.renewed` | то же: арендатор активен (снимает заморозку после отмены) |
| `subscription.plan_changed` | меняет тариф; `plan` должен быть сопоставлен в `PLAN_MAP`, иначе ответ 422 |
| `subscription.cancelled` | замораживает арендатора (данные сохраняются, вход закрыт) |
| `subscription.refunded` | замораживает арендатора |

## Ответы шлюза

| Код | Тело | Что делать площадке |
|---|---|---|
| 200 | `{"status": "processed"}` | готово |
| 200 | `{"status": "duplicate"}` | событие с этим `event_id` уже было — ничего не сделано, повторять не надо |
| 200 | `{"status": "stale"}` | по аккаунту уже обработано событие с более поздним `occurred_at`; старое не отменяет новое |
| 400 | `{"detail": "invalid payload"}` | тело не по схеме — исправить отправку |
| 401 | `{"detail": "invalid signature or timestamp"}` | неверная подпись или метка времени вне окна |
| 422 | `{"detail": "unknown plan"}` | тариф не сопоставлен — сообщить TIREK; повтор пройдёт после настройки |
| 502 | `{"detail": "upstream error"}` | TIREK временно не ответил — **повторить** позже (с новой меткой времени и подписью, тот же `event_id`) |

Порядок доставки не важен: шлюз сравнивает `occurred_at` событий одного аккаунта.
