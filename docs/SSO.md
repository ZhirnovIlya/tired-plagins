# Единый вход: площадка → TIREK

Документ для разработчиков площадки. Пользователь нажимает «Открыть TIREK» на площадке —
площадка выпускает короткоживущий JWT и перенаправляет браузер на шлюз:

```
GET https://<домен шлюза>/sso?token=<JWT>
```

Шлюз проверяет токен, находит организацию-арендатора по аккаунту, получает в TIREK
одноразовый код входа и перенаправляет браузер в кабинет: `<кабинет TIREK>/#/login?code=<код>`.
Пароль пользователю не нужен.

```
браузер ── площадка: «Открыть TIREK»
        ◄─ 302 → шлюз /sso?token=JWT
        ── шлюз: проверка JWT → аккаунт → арендатор → код входа (API TIREK)
        ◄─ 303 → кабинет /#/login?code=…  (код одноразовый, живёт недолго)
```

## Токен

Алгоритм — один из двух, выбирается в настройках шлюза при подключении:

- **HS256** — общий секрет (у шлюза `SSO_JWT_SECRET`), передаётся вне репозиториев;
- **RS256** — площадка подписывает своим закрытым ключом, шлюз проверяет открытым
  (`SSO_JWT_PUBLIC_KEY`, PEM). Предпочтительнее: секрет не покидает площадку.

Шлюз принимает **только** настроенный алгоритм (токен HS256 при настройке RS256 отклоняется).

| Поле | Обязательно | Смысл |
|---|---|---|
| `account_id` | да | id аккаунта (компании) на площадке — тот же, что в вебхуках, строка |
| `sub` | да | id пользователя на площадке, строка; шлюз его не хранит и не пишет в лог, в TIREK уходит только хэш |
| `aud` | да | идентификатор шлюза, выдаёт TIREK (у шлюза `SSO_AUDIENCE`) |
| `iat` | да | время выпуска, unix-секунды |
| `exp` | да | срок действия, unix-секунды. Делайте коротким (минуты): токен в адресной строке |

Имена, почты, телефоны в токен **не кладите** — шлюзу они не нужны и не сохраняются.
Часы площадки и шлюза должны совпадать; допуск задаётся `SSO_LEEWAY_SECONDS`.

### Пример (Python, PyJWT)

```python
import time, jwt

now = int(time.time())
token = jwt.encode(
    {"account_id": "company-42", "sub": "user-7", "aud": AUDIENCE, "iat": now, "exp": now + TTL},
    PRIVATE_KEY_PEM,  # для HS256 — общий секрет
    algorithm="RS256",
)
redirect(f"https://<домен шлюза>/sso?token={token}")
```

`TTL` — срок жизни токена в секундах, согласуется при подключении.

## Что увидит пользователь

| Ситуация | Ответ шлюза |
|---|---|
| всё в порядке | 303 → кабинет TIREK |
| нет `token` | 400, страница «В ссылке для входа нет данных площадки…» |
| токен просрочен, чужой `aud`, неверная подпись, нет обязательного поля | 401, страница «Ссылка для входа устарела или недействительна…» |
| подписка аккаунта не активна (отменена, возвращена) | 403, страница «Подписка на TIREK не активна…» |
| TIREK временно не отвечает | 502, страница «TIREK временно недоступен…» |

Если вебхук о покупке ещё не дошёл, шлюз сам спрашивает TIREK об аккаунте (создание
арендатора идемпотентно) и пускает пользователя, если подписка активна.
